# 03 · 落地批次

五批，每批都能独立验收、独立回滚。顺序的依据是「先让它看起来像个 app，再让它的核心流程对，最后补成品件」—— 因为图标与视觉层级是所有后续页面的地基，先做能避免后面每个新页面都要返工一次。

---

## 批次 1 · 地基：图标 + 主题 token + 组件层级

**不动任何业务逻辑。** 做完这一批，app 的观感问题解决大半，业务还是原样。

- 新建 `apps/ouyu/resources/icons/`，画 18 个图标（规格见 [02 第五节](02-redesign-plan.md#五图标系统)）
- 新建 `apps/ouyu/src/theme.rs`，把 `lib.rs` 里的字面量 hex / 字号 / 间距全部收进 token
- `OuyuNavTab` 加图标 + 选中态；底部导航五格重做
- `OuyuBtn` 系列加尺寸档、disabled、loading、图标位；全局去掉「→」
- 卡片分三级；字号补 17 档；11px 说明文字提到 12–13
- 新增 `OuyuToast` `OuyuEmpty`

**验收**：手机 320 / 412、桌面 1400 三档，五个页面逐页截图，无横向溢出；`cargo test -p octosense-ouyu` 全绿；宿主 Android 风格下进 ouyu，导航图标与系统壳风格一致。

## 批次 2 · 发现页与发布向导

- **新建 `apps/ouyu/src/areas.rs`**：北京约 100 个公共片区，按行政区分组，带类型、别名、拼音首字母（收录标准见 [02 第三节](02-redesign-plan.md#区域选择器--不接地图但要做完整)）
- 时间选择器（今天 / 明天 / 本周 + 7 天日期条）
- `data.rs` 新增 `OppLevel` / `AreaOpportunity` / `opportunity_ranking`；`Publish.area` 从下标改为区域 id，`AREAS` 常量退役
- 「最可能遇见的地方」排序列表 + 阈值不足分段
- 「我的去向」压成紧凑状态条
- `devbar` 移出发现页（暂放到侧栏底部，批次 4 再进设置）
- 发布 FAB + 三步向导；`Publish.day` 放宽到 0..=6
- **区域选择器**：搜索（中文 / 别名 / 拼音首字母）+ 最近去过 + 类型筛选 + 行政区筛选 + 行内机会分档

**验收**：搜索「sltyd」「太古里」「三里屯」三种输入都能命中三里屯一带；不搜索也能按行政区浏览到任一片区；最近去过在重启后仍在；切换今天 / 明天 / 某一天，排序列表随之变化且同一天内多次进入结果一致（固定批次）；阈值不足时上半段为空、下半段显示普通建议；发布向导三步可前进后退，退出丢草稿；预览文案仍是「一行、无身份」。

**不做**：真实地图（[决策 3](02-redesign-plan.md#九已定稿的决策2026-09-17)）。

### 实施时改掉的几处计划

1. **区域详情 sheet 去掉了**。片区上能说的只有名字、行政区、类型、分档 —— 这四项在列表行里已经全在了，再点开一层只会重复一遍。点一行现在直接进发布向导，把这个片区填进草稿。
2. **筛选默认收起**。原计划把类型与行政区两排筛选常驻在搜索框下面，实测 17 个行政区 + 9 个类型在手机宽度下要占掉两百多像素，把列表挤到屏幕外。改成一个「筛选」按钮，展开才占位；启用了筛选时按钮文案会变，不会让人忘了自己还开着过滤。
3. **向导底栏不进滚动区**。第 2 步的片区列表有十八行，底栏若跟着内容走，人得先滚一屏才能点到按钮；又因为换步骤时滚动位置不复位，在底部点「上一步」会回到一屏空白。现在向导拆成「可滚动正文 + 固定底栏」，并且每次换步将正文滚回顶部。
4. **第 2 步保留「下一步」**。原本想用「点一行就往前走」完全代替按钮，但改行程的人常常只改时间、片区照旧 —— 没有按钮就卡在这一步了。两者共存，并把第 2 步的副标题换成「现在选的是『×××』—— 点另一个可以换，不换就直接下一步」。
5. **行内补了时段提示**。区域详情 sheet 取消后，[02 A-4](02-redesign-plan.md) 要求的「时段粒度提示」没了落脚点，现在放到行的第二行：「朝阳区 · 商圈 · 下午最集中」，只到上午 / 下午 / 晚间这一粒度，且未达阈值的片区不给。

### 区域库的规模

`areas.rs` 收了 **106 个北京公共片区**，覆盖 16 个行政区。测试里钉死了三条收录标准：id 唯一且不少于 100 条、片区名必须以「一带 / 周边 / 公共街区 / 城区 / 副中心」收尾（措辞不能精确到具体地点）、名称里不得出现医院 / 诊所 / 小区 / 大厦 / 写字楼 / 中学 / 幼儿园。

## 批次 3 · 现场互认重做（业务核心）

- `RecogStage` 增 `LocationGate` / `Expired` / `NoStock`
- ① 选人屏：删掉入口分叉与「回忆怎么留」
- ② **定位门槛屏（硬门槛）**：未授权不建立会话
- ③ 单一等待态：进度环 + 真实倒计时 + 折叠的二维码区；删 `se_code` / `se_self` / `se_sim_label` / `se_sim`
- ④ 结果屏：成功即出券 + 店家（最多 3 家）+ 「这次回忆怎么留」；取消「领取」步骤
- 异常统一到同一结果屏的 5 种文案
- 模拟入口移到开发者选项

**验收**：走完成功、对方未确认过期、信息不一致（3 次用尽）、未授权定位、同地不成立、无库存六条路径，每条都停在一个有明确出口的结果屏；**未授权定位时确认按钮不可用、会话不建立**；正常路径全程看不到「会话码」「本人提交」「模拟」字样；回忆写入时机仍是「离开成功页时按本次选择写入一次」。

### 实施时改掉的几处计划

1. **会话不再因为切 Tab 作废。** 原来离开相遇页就把进行中的会话丢掉。可窗口有
   10 分钟，中途去回忆页看一眼就作废说不过去；开发者选项也在别的页上，按原做法
   根本够不着。改成：只有已经出结果的会话在离页时按选择写入回忆并清掉，等待中的
   留着，倒计时照跑。
2. **开发者选项里按完一下就跳回相遇页。** 否则结果出在一个当时看不见的页面上。
3. **互认没成立的两条路不问「这次回忆怎么留」。** 超时和信息不一致这两屏上，
   相遇本身还没确认，摆一组「保存 / 隐藏 / 不保存」等于替人认定发生过。改成一个
   「只记一笔回忆」按钮，默认什么都不写。成功 / 同地不成立 / 无库存这三屏照常给
   选择 —— 那三条路上相遇是确认了的。
4. **超时后的「再试一次」不占用 3 次不一致的额度。** 两件事不一样：对方没顾上，
   和两边填的人对不上。
5. **二维码仍然是短码 + 链接文字。** makepad 里没有 QR 编码器，画一张假的二维码
   比不画更糟。
6. **手里还有一张没核销的券时不重复发券。** 一次成功发一张，旧券没核销就不覆盖。
   多张券并存要等批次 4 的券包。
7. **`RewardClaim` 新增的 `expires_on` / `token` / `terms` 全是 `Option`。**
   `load_from` 在解析失败时会整个回退，字段改成必填等于让老 `state.json` 连回忆
   带联系人一起消失。

### 宿主一致性（这一批的那次）

在 Omarchy 宿主里跑了一遍（1400×900）：图标、圆角、配色与独立进程一致，互认四屏
（选人 / 定位门槛 / 等待 / 结果）都正常。独立进程里另外核了 412×892 与 336×640
两档，没有横向溢出。Android 宿主那一条没跑 —— 这台机器上没有可用的模拟器。

## 批次 4 · 「我」页 + 我的券 + 设置隐私 + 四态 + undo

- 导航第五格改「我」
- 「我的券」：`wallet` 持久化，可用 / 已核销 / 已过期三分区
- 设置：定位权限、通知开关、数据与隐私、开发者选项、关于
- 空 / 加载 / 错误 / 离线四态统一组件铺到全部列表页
- 删除类操作改 5 秒 undo；不可逆操作保留二次确认

**验收**：领到的券离开成功页后能在「我的券」里找到，且带有效期；清除本机数据后重启，回忆 / 券 / 联系人全空且不报错；券里不含任何联系人 / 坐标 / 相遇日期字段（代码级检查 + 一条单测）。

### 实施时改掉的几处计划

1. **设置行没有行首图标，四态不换图标，开关用两枚滑块。** 这三处都是同一个原因：
   `script_apply_eval!` 的作用域里没有 `crate_resource`、`Align` 和 `Inset`（和
   `Fill`、`theme.*` 一样），运行时既换不了 svg 也挪不动对齐。于是图标一律在标记
   里写死 —— 设置行干脆都不要（否则一行一个预设得复制一份），四态只改这一页自己
   那个图标的颜色（正常 `#x3c4c6b`、出错 `#ff9eab`、加载与离线 `#x5d6f8d`），开关
   在轨道两端各放一枚滑块、按状态显隐其中一枚。一页一个图标本来也比四页共用一个
   通用图标好认。
2. **「删除联系人」保留那一行确认，「删除回忆」改成直接删 + 撤销。** 原计划是
   「删除类一律换 undo」。可删联系人那一行不只是「确定吗」，它带着「同时删除 TA
   的全部回忆」这个真正的选择 —— 这个选择 5 秒撤销条表达不了。所以那一行留着，
   确认删除之后仍然给 5 秒撤销。单条回忆删除和「删除全部回忆」没有这种附带选择，
   直接删 + 撤销。
3. **撤销存的是整份快照，不是逆操作。** `UndoSnapshot` 把联系人和回忆两张表整个
   拷一份，撤销就是整份放回去。逆操作要为每种删法各写一遍、还要还原顺序，出错的
   面积比多拷一份大得多。
4. **「清除本机数据」不走撤销，保留二次确认。** 它真的不可逆（撤销条一过就没了），
   而且清的是数据不是设置 —— 通知开关和定位授权留着，否则清一次数据等于把人的
   隐私选择也一起清掉。
5. **券包三个分区各只有四个固定位置。** 和发现页、回忆页一样是演示规模的写法，
   真实版本要换成列表控件。超过四张的暂时看不见。
6. **「空」没有进 `ListState` 枚举。** 空是数据说了算的，加载 / 出错 / 离线是网络
   说了算的；混进一个枚举会让「你还没有券」被当成一种故障来显示。四个态共用
   `OuyuEmpty` 一个组件，但「空」由 `n == 0` 决定。
7. **导出文件与 `state.json` 同构。** 不额外拼坐标、地点或相遇日期进去 —— 导出是
   把本机已有的东西给人，不是重新组织一份更详细的。
8. **`RewardState` 是算出来的，不是存下来的。** 02 七.3 把它画成 `RewardClaim` 的
   一个字段。可「已过期」这件事随日子变：一台搁了几天才打开的手机，存下来的分区
   就是错的。改成 `state(today)` 按当天算，落盘的只有 `redeemed` 和 `expires_on`。

### 这一批的三档宽度

独立进程里逐页看了 336×640、412×892 和 1400×900：券包、设置、券卡、开关行都正常
换行，没有横向溢出。按 03 的口径，宿主一致性这一批不跑（只在批次 3 和批次 5 后跑）。

## 批次 5 · 成品件补齐

- 首次启动引导 3 屏 + 隐私同意
- 通知两类（发布到期、券到期），默认关闭
- 回忆页：按月分组、按人筛选、详情与备注编辑、搜索（隐藏记录不进搜索）
- 熟人页：手动添加、字母索引、合并重复
- 成就页：曲线数据表（06 明确要求）
- 桌面 aside 改成当页上下文面板

**验收**：隐藏一条回忆后搜索不到、成就曲线数值下降，恢复后回来（02 F / 06 的口径）；成就数据表的数字与曲线一致；引导可跳过并能在「我」页重看。

### 实施时改掉的几处计划

1. **开场三屏的图标写死在标记里，按步显隐。** 又是批次 4 那个坑：
   `script_apply_eval!` 的作用域里没有 `crate_resource`，运行时换不了 svg。三枚
   图标各裹一层 `View`（`Icon` 自己没有 `visible`），走到哪一屏亮哪一枚。
2. **藏导航的判断挪进了 `apply_shaping`。** 一开始写在 `update_page_visibility`
   里，结果那边刚藏完，紧跟着的重排又把顶栏和底栏放回来了。现在
   `apply_shaping` 自己知道「在开场三屏里」，并多一个 `reshape()`：形态没变
   （还是那个宽度）但「要不要给导航」变了的时候，按缓存的形态再跑一遍。
3. **开场三屏在宽屏上收成一条 620px 的列。** 1280 宽下一行正文能拉满整屏，读起来
   会跳行。留白按真实像素宽度算，所以多存了一个 `last_size`，并且开场三屏开着的
   时候 `update_responsive` 不再因为「档位没变」提前返回。
4. **切 Tab 会丢发布草稿。** `set_tab` 现在顺手把 `wizard` 清掉。原先切走之后
   发布向导还留在屏幕上（底栏高亮「我」，正文却是发布第 1/3 步）。这和批次 2
   写的「退出丢草稿」是同一个口径。
5. **回忆的隐藏 / 恢复 / 删除 / 写备注收进了一张详情页。** 计划里这些动作都摆在
   列表行上。四个按钮一行，手机上永远在换行，而且「删除」离手指太近。现在行里
   只有日期、一句话和「打开」。
6. **搜索时把「已隐藏」整段收起来，而不是把它过滤空。** 隐藏的本来就不参与搜索，
   留一个空壳在那里只会让人以为「搜过了，没有」。收起来的同时明说一句
   「隐藏的回忆不参与搜索。」
7. **通知是应用内的横幅 + 60 秒轮询，不是系统通知。** 这份草图没有系统通知通道。
   两类通知的判定（`due_notices`）是真的：到点才出，开关默认关着，已经发过的记在
   一个只活在内存里的 `notice_sent` 里，同一次运行不重复弹。开发者选项里那两个
   按钮走的也是这同一个 `due_notices`，只是把表拨到点上。
8. **字母索引用的是姓氏表，不是完整拼音表。** `alpha_key` 先认复姓（欧阳 / 司马 /
   诸葛 …，长的先匹配），再剥「老 / 小 / 大 / 阿」这类前缀，然后查一张 250 条的
   常见姓表；认不出来的归「#」，排在最后。整套拼音表要带一个词库，这份草图用不上。
9. **合并用「点两下」，不是勾选多选。** 第一下选要并走的那一位（那一行的按钮变
   「取消」，其它行变「并到这里」），第二下选目标。方向说死了：被并走的那一位会
   消失，回忆连同称呼快照一起转过去。合并之后给的是**撤销条**而不是一句提示 ——
   撤销比「转过去 N 条」有用，而 toast 会把撤销按钮盖掉。
10. **列表行的下标改成指 `contact_order` 而不是 `state.contacts`。** 加了字母排序
    之后，行的顺序和存储顺序不再一致；沿用旧下标的话，点「删除联系人」删掉的会是
    另一个人。
11. **成就页的曲线数据表在更早的批次里就做掉了。** 这一批只补了验收：数据表的
    每周数字与曲线的折点一致（隐藏一条之后两边一起降，恢复之后一起回来）。
12. **桌面 aside 是「多一张卡」，不是「换掉五张卡」。** 原来那五张隐私说明卡是
    产品口径，不是装饰，留着。顶上新增一张跟着当前页和当前数据走的摘要卡，三行
    一律只说「你自己的那一份」（自己的发布、自己的券、自己的回忆、自己的名单），
    不放任何跟别人有关的计数。
13. **回忆行上那个「有备注」的小笔图标做了又拿掉了。** 行里本来就把备注整句显示
    出来，图标是重复的；手机宽度下它还会被挤到一个尴尬的位置。

### 这一批的三档宽度

独立进程里逐页看了 320×700、412×892 和 1400×900：开场三屏、回忆详情、回忆页搜索、
熟人页的添加行与合并说明条都正常换行，没有横向溢出。

### 宿主一致性（批次 5 的那一次）

两档都跑了，都过：

- **Omarchy 桌面 1400×900**：侧栏 + 右栏上下文卡都在，图标风格、圆角半径和
  配色与壳自己的 chrome 是一套。
- **Android 风格 412×892**：发现 / 相遇 / 熟人 / 我 四页都是手机形态 ——
  底部五格导航（第五格是「我」）、没有侧栏也没有右栏，字是原生像素。
  这一批新加的熟人页添加行、字母索引头、合并按钮在这个宽度下都排得开。

踩到一个不是 bug 的坑，记一笔：**在已经开着 ouyu 的宿主上直接换桌面风格、
再改窗口尺寸，看到的是桌面布局被缩进 412 的表面里**（字又小又糊，侧栏还在）。
Android 的「主页」手势是把应用放到后台而不是关掉，模块实例带着旧的 1400 表面被复用了。
重开宿主、先换风格再进应用，就是干净的手机布局。而改尺寸之后才打开的
Reference 应用是清晰的原生 412。所以这是宿主侧的模块表面缓存，
不在 ouyu 这份草图的范围内。

## 批次 6 · 收掉调试件，行踪改成多条

五批做完之后按实际使用再收一次：

- **开发者选项整段删掉。** 稀疏场景、替对方按一下、列表四态、通知立刻到点 —— 这些都是草图期
  的脚手架，产品态用不到。列表只剩「有 / 空」两态，`apply_list_state` 相应缩成空态一件事。
- **界面模式按钮删掉。** 侧栏底部和顶栏上那枚「自动 / 手机 / 大屏」拿掉，`shaping_for` 只看
  拿到的 surface 尺寸；手机 / 桌面的切换在宿主的样式菜单里，应用内不再另给一个开关。
- **顶栏所有形态都在，右边是当页主动作。** 发现页是「发布行踪」（原来的悬浮 ＋ 按钮和状态条
  上的「发布」都收掉），相遇页首屏是「确认相遇」，别的页收起。
- **相遇页首屏 = 原「我」页的成就内容。** 频率曲线、里程碑、分享卡搬过来做默认页；「本机统计」
  那张摘要卡整个删掉。点「确认相遇」才进选人 → 定位 → 等待 → 结果，选人屏加了「返回」。
- **行踪可以有多条。** `OuyuState.publish` 变成 `publishes: Vec<Publish>`，每条带 `id` 和绝对
  日期，到期按日期 + 时段各自算；最多保留 20 条到期记录，行踪跟着落盘（回声照旧不落盘）。
  「我」页只剩两块：「我的行踪」（最近发布的三条进行中的，可修改 / 删除；标题右侧「更多」
  进全部历史，到期的只读）和券包 / 设置 / 关于三个入口。演示数据自带三条进行中、三条到期的
  行踪，从没发布过的空存档不会盖掉它们。
- **发现页收成两张卡。** 「什么时候出门」和「最可能遇见的地方」；行踪状态条、回声、
  「我们碰到了」三张卡删掉 —— 发布在顶栏，互认在相遇页，回声没有了入口。
- **文案过一遍。** 「只影响排序」「设计草图 · 模拟数据」「设计稿 v0.4」「虚构示例」「（模拟）」
  「分档」「成就页」「本机熟人」这类给自己看的词全部改成用户的话；「本机熟人」→「我的熟人」。
- 快照与通知：AI 快照取最先结束的那一条；「行踪快到期」也只提醒今天最先结束的那条。

## 贯穿全程的约束

每一批合并前都要过这几条，不合格不进下一批：

1. **无横向溢出**：手机 320 / 412、桌面 1400 三档逐页检查。
2. **测试通过**：`cargo test -p octosense-ouyu --offline`，新逻辑（排序分档、状态机映射、券生命周期）都要有纯函数单测。
3. **隐私红线自检**（每批都跑一遍这张表）：

| 检查项 | 依据 |
|---|---|
| 发现页任何位置都没有身份、人数、距离、实时位置 | 02 B |
| 阈值不足时不给熟人机会，且不解释是谁没参与 | 02 B |
| 定位只在互认路径请求一次，坐标不落盘、不进日志；未授权即不建会话 | 02 D / G |
| 区域库不含楼宇 / 小区 / 医院 / 学校内部，片区粒度 ≥1km | 02 A |
| 互认失败提示不揭示谁填了谁、不揭示账号是否存在 | 02 D |
| 券不含联系人 / 坐标 / 相遇日期 | 02 H |
| 分享图默认不含姓名、地点、日期、曲线 | 06 |
| 隐藏记录不进搜索、提醒、AI、成就统计 | 02 F / 06 |

4. **宿主一致性**：在 OctoSense 壳里用 Android 风格（412×892）与 Omarchy 桌面（1400×900）各跑一次，确认图标风格、圆角、配色和系统其余部分是一套。

   实施时改了频次：不再每批都跑。壳里只能看到图标、圆角、配色这三样东西，它们在批次 1 就固定下来了，后续批次改的是页面结构与业务流程；把一次完整的宿主烟雾测试拆成五次，成本不小而能发现的东西几乎不变。改成：**批次 3 做完一次（互认流程重写，页面结构变动最大），批次 5 做完再一次**；其余批次用独立进程里的 320 / 412 / 1400 三档截图代替。

## 时间与顺序上的取舍

如果要更快看到效果，可以把**批次 1 和批次 3 调到最前**（地基 + 互认），因为这两批分别解决了你提的「没有 icon / 不精致」和「业务上不对」；发现页重构（批次 2）虽然是你明确点名的，但它依赖批次 1 的组件层级，硬插到前面会做两遍。

顺序定为 1 → 2 → 3 → 4 → 5。
