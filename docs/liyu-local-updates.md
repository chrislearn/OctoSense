# LiYu 局部更新与闪动排查（2026-09-27）

基线：e3a17d6。检查范围：apps/liyu 全部事件、导航、刷新和绘制代码，以及 OctoSense 宿主的模块与窗口绘制路径。

## 根因与影响面

原 start_fade 将 alpha 置为 1；draw_walk 在整个 tile 的 full rect 上画背景色；随后 NextFrame 在 150ms 内反复重画根视图。这是主动遮住界面造成的闪动，不是字段修改必须重新创建应用。

| 入口 | 原行为 | 修复 |
| --- | --- | --- |
| 显示名、手机号、邮箱、地址、称呼的修改 | 全屏遮罩、动画时钟、根重绘 | 更新账号工作区，保留导航、输入、滚动 |
| 主菜单切换 | 同一全屏遮罩 | 直接呈现目标页面 |
| 详情/覆盖页打开、返回 | 同一全屏遮罩 | 更新页面显隐与来路栈 |
| 结束引导 | 同一全屏遮罩 | 更新页面和通知 |
| 心愿结算成功 | 同一全屏遮罩 | 更新结算结果 |

移除遮罩、专用 NextFrame、逐帧根重绘，以及绑定到该时钟的手机详情 margin 移动。手机继续支持分类→详情→编辑→返回，界面直接切换。普通编辑没有 ScriptReapply；主题变化/LiveEdit 仍需要全局样式更新。

## 更新成本

- 账号工作区拥有独立 draw list（new_batch），编辑/取消/保存请求该工作区绘制，不主动刷新全局导航。
- set_text/show/set_chip_group 对相同值跳过赋值，避免重复文本选择处理、显隐更新和选中动画。
- 头像预览字节未变化时复用 GPU 纹理；变化、清空和主题重应用后正确更新。资料头像和账号摘要共享纹理。
- after_data_change 只更新当前可见的列表或钱包；隐藏列表在 set_tab 进入时刷新。启动、登录、主题变化保留 refresh_all。
- 在个人资料/联系方式/地址间切分类不重复 open_profile，避免每次重载服务器资料和清空头像编辑状态；重新进入资料仍走真实加载。

宿主 redraw_all 是 UI 绘制失效请求，窗口到达/开合淡入由窗口生命周期驱动。没有发现它因 LiYu 修改按钮而重开窗口。这里没有改动宿主正常窗口动画或框架渲染器。首次显示尚无绘制 Area 的控件，框架可能要求整帧布局；正常绘制不应被说成闪白或应用重建。
