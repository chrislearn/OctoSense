# 04 · OctoSense 接入与迁移差距

## 当前演示与新版设计不能混称

当前已有 `apps/ouyu`，本轮只改设计 / HTML，不修改 Rust 行为。根据 `src/data.rs`、`src/ai.rs`、`src/lib.rs` 的现有结构，旧演示使用本机模拟熟人 / 商户、具名空闲、结伴卡、持久化 JSON；新版的匿名匹配、双人互认与奖励验证还没有后端。

| 旧行为 | 新版目标 | 迁移要求 |
|---|---|---|
| 熟人姓名、区域、空闲时段绑定 | 发现只显示匿名区域机会 | 发现 UI / 数据接口彻底移除身份字段，不只是隐藏头像 |
| `Contact.area/free_start/free_end` | 本机联系人与发布分离，无好友授权 / 安装状态 | 发布短期存储，联系人不携带他人行程 |
| 手动位置 `my_pos` 持久化 | 不保存行踪 | 移除位置历史字段、清理旧数据，不能只停止显示 |
| `Sent/Accepted/Done`，选餐厅算完成 | 线下双方独立互认才算相遇 | 新现场会话状态机；约店与领券不等于见过 |
| 自动记「和谁 / 哪儿」，亲密度累积 | 每次相遇选择保存；默认无地点 | 计数由已保存回忆推导，删除后减少；清除旧地点 / 评分 |
| JSON 保存全部状态 | 仅联系人 / 私人回忆长期保存 | 发布、验证输入、临时会话分离，有期限与清除验证 |
| `who_is_free` 等具名 AI 工具 | 匿名聚合 / 通用建议 | 接口契约与输出一起改变，避免 AI 成为泄露旁路 |

vCard 导入就是本机联系人来源，无需对方安装或批准，不查询注册状态。实际匹配只能基于有效发布数据，不会给未发布的人生成位置。现有本地模拟结伴回应不是双人确认或匿名协议的验证。

## 应用形态

继续使用 `apps/ouyu` 的 Makepad 托管进程 / `AppModule` 结构与宿主主题，避免重复建应用。JSON 持久化根由 `MAKEPAD_HOME` 注入，无此变量时现有演示回退内置数据。

HTML 草图在 `ouyu/design/prototype` 独立运行，不参与 Rust 构建、不读取用户现有 state.json。正式应用不直接复用草图模拟校验。

## 落地顺序

1. **产品合同先定**：匿名威胁模型、单向本机联系人匹配、阈值与稀疏回退、期限、成功 / 失败定义；无安装查询和好友授权。
2. **本机界面**：首页整合、粗粒度发布预览、单次回忆选择、联系人计数与删除、逐条隐藏 / 恢复；处理旧位置与旧记录迁移。
3. **模拟状态机**：现场会话、独立互认、定位拒绝 / 不一致 / 过期 / 缺库存。双客户端模拟，不能用固定 2 秒成功代替验证。
4. **服务协议**：隐私联系人匹配、匿名机会批次、免安装网页确认、现场身份验证、限频、同地证明。协议安全评审后再启用真实位置 / 电话。
5. **奖励服务**：独立防重键、一次性券、库存、核销、防重放与客服。商户接口不可查询关系。
6. **成就 / 分享**：从可见回忆推导周曲线和徽章，隐藏 / 删除重新计算；生成无他人身份的本机分享图，明确公开频率的例外。详见 [06](06-achievements-sharing.md)。
7. **AI 收口**：移除旧具名行程工具，最小权限与数据输出测试；最后验证所有清除期限与日志 / 缓存 / 备份。

## 必须验证的安全与产品检查

- 小圈、重复查询、调整联系人子集与多账号无法轻易推断单个发布者；无法承诺绝对匿名的地方明确说明。
- 发现 API / DOM / AI 输出无身份与行程绑定，内部标识不进入分享链接。
- 互认失败不暴露对方输入或账号存在；同名不能领券；定位拒绝可以完成普通回忆。
- 隐藏仍保存、恢复可见；不保存不新增；删除清理索引与衍生字段；对方日记与风控例外解释准确。
- 过期发布立即退出匹配、缓存按期限清除；重启 / 换机不能恢复已删除内容。
- 同一会话 / 券反复请求不会重复记忆、发券或核销；无券不影响普通相遇成功。

这些是后续正式实现所需的检查，不是本轮 HTML 已提供的隐私保证。
