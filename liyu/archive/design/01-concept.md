# 01 · 给生活留一点偶然

## 到底做什么

偶遇帮助原本认识的人，在各自正常生活中多一次线下重逢。用户说「我今天下午可能在这一带」，应用给出不指向具体人的机会提示。**见面前不知道是谁；在线下认出彼此后，才由双方确认相遇。**

解决「其实都在附近，却没有见到」和「正式邀约太重」的问题。成功是自愿确认的真实见面，以及见面是否值得。发布量、定位时长、广告点击量不是产品目标。不做找人雷达、陌生人配对、公开动态或打卡排名。

## 自然的故事

1. 出门前，小林选「今天下午 · 三里屯一带 · 顺路走走」，预览别人能看到的内容后发布。
2. 只展示达到匿名保护条件的区域机会，不显示是谁、几个人、头像、距离或更新时间。样本不足时，只有不依赖他人行程的城市建议。
3. 可以留一个通用「咖啡回声」，没有私聊、自定义暗号、响应者与已读状态。不生成约定，仍按自己的计划活动。
4. 咖啡店真的碰到朋友，两人聊天后分别打开「我们碰到了」。此时才选择本机已认出的联系人或填写已经知道的姓名 / 电话。
5. 双方交叉互认一致、短期同地验证成立，各领一张附近相遇礼；不用消费也算成功相遇。
6. 每次相遇选择保存 / 隐藏 / 不保存本次回忆，默认只存「和谁 · 哪一天」，不自动保存地点、路线、精确时刻、照片或聊天。熟人页显示已保存相遇次数，允许删除联系人和回忆。

熟人来自自己的通讯录，不需要双向授权，不需要知道对方安装或注册状态。发布即参与本次机会，撤回即退出，不另设参与开关。单人可以独立留下私人回忆；大额相遇礼才需双方现场确认，另一位可通过免安装网页参与。

核心循环：`发布模糊去向 → 匿名机会 → 正常生活中相遇 → 双方互认 → 可选奖励 → 私人回忆`。

行程发布不要求持续定位。领同地券时才短时请求定位，拒绝仍能确认普通回忆。

## 隐私边界

| 阶段 | 能知道 | 不能知道 |
|---|---|---|
| 发布 / 发现 | 模糊街区、粗时间段、通用意愿 | 发布者、头像、电话、人数、实时坐标、在线状态 |
| 回声 | 区域通用活动 | 发送 / 响应者、已读、单人响应数 |
| 现场互认 | 已在线下认出的联系人、自己的提交状态 | 对方填写内容、后台候选名单 |
| 成功后 | 本次互认联系人、自己的券 | 对方资料、过去行程、通讯录与其他相遇 |
| 商户 | 券是否有效、核销结果 | 两人姓名、关系、位置与行程 |

「匿名」是应用不披露谁发布了什么，不是让现实中的熟人忘记身份。本机通讯录仍有姓名；认证 / 匹配平台可能掌握关系元数据，不能宣称平台也绝对不知道。

## 稀疏场景不能假装匿名

圈子只有一个人时，「有熟人在附近」本身就可能暴露身份。默认机会阈值暂设 **至少 5 位不同、有效的匿名发布候选**，无需双向好友授权，固定区域、固定时间桶、不给精确人数、不开放任意圈选与连续查询。

5 是设计起点，不是数学保证；共谋、外部信息、反复比较仍可能推断身份。上线前需威胁测试决定阈值。未达阈值不回退显示单人、不告诉用户还差几人，只给普通城市建议。小圈用户仍可发布、现场互认、按规则领奖。

## 趣味要帮助见面

- **城市小签**：随机散步、书店或咖啡主题，空状态也有乐趣；不依赖他人位置、不必消费。
- **匿名回声**：固定活动选项给相遇一个由头；不做匿名聊天室，防止职业、姓名或暗号辨认。
- **相遇礼**：真实互认后的赞助券；金额与门槛共同展示，不诱导开定位换未知奖励。
- **私人回忆卡**：可选「聊得很开心」；不做亲密度排名，不催促「好久没见」。
- **个人成就与分享卡**：看 4 / 8 周相遇频率和生活里程碑；主动导出汇总分享图发朋友圈，不带他人姓名与行程。隐藏和删除后重新计算，见 [06](06-achievements-sharing.md)。
- **自由休息**：撤回、忽略都没有惩罚，无额外参与开关、连续签到或关系积分压力。

## MVP 与验证

先做一个城市、当天 / 明天、固定粗时段的两人流程。暂不做周期行程、多人局、精准约见、自动日历、照片及原始回忆公开分享；可做本人主动生成的汇总成就卡。

验证新用户能否在 30 秒理解「不知道谁」、发布预览是否准确、普通确认能否在 1 分钟完成；拒绝定位、对方未确认、没有券时是否有明确下一步。评估有效见面、满意度、投诉、异常核销与奖励成本；总体漏斗不记录关系图或位置历史，稀疏统计也需保护。
