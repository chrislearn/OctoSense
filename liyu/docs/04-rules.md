# 04 · 规则

这里的每条规则都对应 `apps/liyu/src/data.rs` 里的一个函数或常量，并有单元测试。

## 1. 解谜

| 规则 | 值 | 代码 |
| --- | --- | --- |
| 每份礼物的机会 | 3 次 | `MAX_ATTEMPTS` |
| 猜错后 | 机会 −1，礼物不消失 | `LiyuState::submit_answer` |
| 3 次用完 | 直接揭晓，送礼人身份保密 | 同上，`identity_known = false` |
| 无条件领取 | 打开即揭晓，身份可见 | `LiyuState::open`（`Unlock::Free` 分支） |

**长度上限**（按字符计）：线索 / 问题 / 提示 30（`CLUE_MAX_CHARS`）、答案 20（`ANSWER_MAX_CHARS`）、
寄语 40（`MESSAGE_MAX_CHARS`）、称呼 16（`NICKNAME_MAX_CHARS`）。

**答案比对**（`normalize_answer`）：去掉首尾空白 → 转小写 → 去掉所有空白与标点
（中英文标点都算）→ 全角字母数字转半角。比较规范化后的字符串是否相等。

- 私密问答 / 专属暗号：与送礼人设置的答案比对；
- 猜我是谁：答案是送礼人的**称呼**，可以有多个别名，用 `/`、`、`、`,`、`，` 分隔，
  命中任一个即算对（如「林舟 / 舟舟 / 阿舟」）；
- 空答案不算一次机会，提示「先写个答案」。

**候选人芯片**（猜我是谁）：真送礼人 + 熟人 + 通讯录里的名字去重，取 6 个（`CANDIDATE_COUNT`），
按礼物 id 做种子确定性打乱（同一份礼物每次打开顺序一致）。真送礼人一定在里面。
身份保密时，礼盒和契约页都显示「一位神秘的朋友」。

## 2. 契约

- 长度 1–24 字（按字符计），首尾空白去掉；
- **禁用词**（`BANNED_WORDS`）：转账、借钱、红包、还钱、现金、打钱、贷款 —— 命中提示「契约只写轻约定，不涉及钱」；
- 收礼人必须打开「我同意」才能「收下」；**同意契约即揭晓送礼人身份**（契约要有对象）；
- 换购 / 折现 → 契约不生成；
- 期限 = 收下日 + 7 天（`PACT_DAYS`）；逾期只显示天数，不惩罚；
- 「提醒 TA」每条每天最多一次，超过 toast「今天已经提醒过啦」。

## 3. 费用

金额单位是**分**（`i64`）。

```
fee(price, pct) = max(¥1 (MIN_FEE), ceil_to_yuan(price × pct / 100))
```

| 操作 | 费率 | 例（¥109） |
| --- | --- | --- |
| 折现 | 8%（`CASHOUT_FEE_PCT`，`cashout_quote`） | 手续费 ¥9（8.72 → 9），退回 ¥100 |
| 换购 | 5%（`EXCHANGE_FEE_PCT`，`exchange_credit`） | 手续费 ¥6（5.45 → 6），抵扣额 ¥103 |
| 撤回 / 过期退回 | 0 | 全额 ¥109 |

换购多退少补：`diff = 抵扣额 − 新礼物价格`

- `diff ≥ 0`：余额 +diff；
- `diff < 0`：先从余额扣，扣到 0 为止，剩下的记一条模拟支付。

送礼付款（`pay_split` + `send_gift`）：结算页开启「用余额抵扣」时，余额抵 `min(余额, 价格)`，
剩下的用选中的付款方式（`PAY_METHODS`：微信支付 / 支付宝 / 银行卡，全是模拟）；关闭时全部走付款方式。
流水备注写清楚怎么付的：「余额抵 ¥20 · 微信支付 ¥879」/「余额抵 ¥109」/「支付宝 ¥109」。

「去结算」前和付款时跑同一套校验（`check_send` = `send_gift` 的前两步：`validate_draft` + `check_claim`），
所以结算页只会因为付款本身出错。

余额永远 ≥ 0（所有扣款都先取 min）；不可提现。

## 4. 过期与撤回

- 收到的礼物 7 天（`EXPIRE_DAYS`）内没有揭晓 → 已过期，礼物回到送礼人：
  - 我是收礼人：状态变「已过期」，列表显示「已退回给 TA」；
  - 我是送礼人：状态变「已过期」，余额 + 全额，记一条「退回」流水；
- 过期检查在启动时和每 60 秒轮询时各跑一次（`LiyuState::sweep(today)`），幂等；
- 撤回：只有送礼人、只在「待拆」状态可以；全额退回余额。
- **约好日子送到的礼物**（`booked_on` 有值，`sent_on` 是约好的那天）：
  - `sent_on > today` 时是「待送达」（`is_scheduled`），收礼人的礼盒里不出现（`received`）；
  - 7 天过期从送到那天算，不从下单那天算；
  - 送礼人在送到之前随时可以撤回。
- 撤回 / 过期退回的礼物如果认领了心愿，那件心愿马上放开（`release_wish`），别人还能再送。

## 5. 心愿单

### 5.1 上限（`data.rs` 常量）

| 规则 | 值 | 代码 |
| --- | --- | --- |
| 一张心愿单最多几件 | 8 | `WISH_MAX_ITEMS` |
| 标题 | ≤ 16 字，不写就叫「阿岚的生日心愿单」 | `WISH_TITLE_MAX_CHARS`、`WishDraft::default_title` |
| 想说的话 | ≤ 40 字，可不写 | `WISH_NOTE_MAX_CHARS` |
| 说个大概的「要求」 | ≤ 20 字，可不写 | `WISH_WANTS_MAX_CHARS` |
| 日子 | 今天 … 今天 + 180 天 | `WISH_MAX_AHEAD_DAYS` |
| 日子过后还能认领几天 | 7 天 | `WISH_GRACE_DAYS` |
| 提前几天提醒好友 | 3 天 | `WISH_NOTICE_LEAD_DAYS` |
| 场合 | 生日 / 结婚 / 乔迁 / 毕业 / 宝宝 / 其他 | `OCCASIONS` |
| 说个大概能选的类 | 电视 耳机 音箱 投影仪 空气炸锅 扫地机 床品 餐具 灯 绿植 鲜花 蛋糕 咖啡 盲盒 玩具 推车（16 类，对应商品的 `kind`） | `WISH_KINDS` |
| 预算档 | 不限 / ¥100 / ¥300 / ¥500 / ¥1000 / ¥3000 / ¥5000 | `WISH_BUDGETS` |

**进行中**（`Wishlist::is_open`）= 没被提前结束（`closed_on == 0`）且 `today ≤ 日子 + 7`。
不在进行中的心愿单好友还看得到，但不能认领；我自己的不能再编辑。

### 5.2 发布 / 编辑校验（`validate_wish`，只报第一条）

1. 标题最多 16 个字
2. 想说的话最多 40 个字
3. 日子不能早于今天（编辑时日子没改过不算 —— 已经过了日子的单子还能改文字）
4. 最多提前半年发布
5. 至少放一件心愿
6. 一张心愿单最多 8 件
7. 选一下想要的是什么（说个大概的，类必须在 `WISH_KINDS` 里）
8. 要求最多 20 个字
9. 同一件放了两次（具体的商品不能重复；说个大概的同一类可以放两条）
10. 只能改自己的心愿单
11. 已经有人认领的心愿不能删（编辑时认领过的那几件必须原样保留）

「给谁看」空 = 所有熟人；名字去掉首尾空白、丢掉空的。分享用链接 `liyu://w/<id>`。

### 5.3 两种心愿与候选（`wish_candidates`）

- **具体的**（`item = Some(i)`）：候选只有这一件；送的必须是同一件（`fits`）。
- **说个大概的**（`item = None`，`kind` + `max_price` + `wants`）：送的只要是同一类（`kind` 相同）就算兑现，
  预算只是参考。候选这样排：
  1. 同类的全部商品；
  2. 要求里的尺寸（「55 寸以上」「65寸」→ 下限 55 / 65）是**硬条件**：只留尺寸标签 ≥ 下限的；
     一件都不剩时放宽尺寸；
  3. 剩下的字按空白和 `，,、/;；·+和` 拆成关键词，去掉「最好 / 要 / 的」和「以上 / 以内 / 左右 / 都行 / 随便」；
     每个关键词拿去碰商品的标签、名字、介绍，碰上算一次命中；
  4. 预算内有：只留预算内的，按命中数从多到少、再按价格从低到高；
     预算内一件都没有：全部留下按价格从低到高，都标「超出预算」；
- 每个候选带一句理由（`WishMatch::reason`）：「符合 55寸 · 4K · 预算内」/「预算内」/「超出预算」。
- 例：「电视 · ¥3000 以内 · 55 寸以上」→ 声屿 S6 55"（¥2499）、澄光 Q5 55"（¥2699）、澄光 Q6 65"（¥2999）；
  43 寸的声屿 Mini 被尺寸挡掉，Q7 / Q9 超预算不出现。

发布页的实时预览就是拿草稿跑一遍 `wish_candidates`，所以主人看到的和送礼的人看到的是同一份列表。

### 5.4 认领（`check_claim`，在 `send_gift` 里和付款一起生效）

依次检查，第一条不过就报错：

| 情况 | 提示 |
| --- | --- |
| 没从心愿单来却约了以后的日子 | 只有心愿单上的礼物能约好日子送 |
| 是自己的心愿单 | 这是你自己的心愿单 |
| 心愿单不在进行中 | 心愿单已经结束了 |
| 那件已经被认领 | 这件已经有人送了 |
| 送的东西对不上 | 心愿单上要的是另一件 / 要送心愿单上说的那一类 |
| 约的日子晚于 TA 的日子（日子已过则晚于今天） | 送到的日子不能晚于 TA 的日子 |

通过后：收礼人固定为心愿单主人（送礼页的「送给谁」被忽略），礼物记下 `wish_id`；
那件心愿变「我送的」（`WISH_BY_ME`），记下礼物 id、认领日、实际送的商品。
**一件心愿只能被一个人认领**，先付款的算数。

### 5.5 结束、删除、放开

| 操作 | 条件 | 结果 |
| --- | --- | --- |
| 提前结束 `close_wish` | 自己的、进行中 | `closed_on = today`；好友还看得到，不能再认领 |
| 删除 `delete_wish` | 自己的、**没有一件被认领** | 整张删掉；有人认领过时提示「已经有人认领了，只能结束，不能删除」 |
| 加一件 `add_to_wishlist` | 自己的、进行中、没重复、没满 | 从商品详情「加到我的心愿单」；没有进行中的单子时界面转去发布一张 |
| 放开 `release_wish` | 认领它的礼物被撤回或 7 天没拆过期 | 那件心愿回到「还没人送」 |

礼物被收下、换购、折现都**不**放开认领：心意送到了，换成什么是收礼人的事。

### 5.6 隐私

- 好友那边只看到每件「还没人送 / 已有人送 / 你送的」，不知道是谁送的、送的哪一款；
- 主人那边揭晓前只看到「已被认领」（约好日子的加「· 9 月 28 日送到」，送到后「· 礼物在礼盒里等你拆」）；
  揭晓且身份不保密后才写「林舟 送的」—— 和普通礼物的悬念规则一致；
- 心愿单通知（`NoticeKind::WishSoon`）只说「林舟的生日还有 3 天，心愿单上还有 2 件没人送」，
  不说谁送了什么；设置里可以关（`notify_wish`，默认开）。每次最多一条，挑日子最近的一张
  （进行中、还有没人送的、日子在 0–3 天内）。

## 6. 隐私与风控

- 礼卡（礼卡页、礼卡图片、链接）只含：玩法、线索 / 问题 / 暗号提示、「拆开之前，是什么、谁送的都保密」、「礼遇 LiYu」。
  **不含**礼物名、价格、送礼人、答案；
- 「送给谁」是送礼人的备注，只在送出的列表里给自己看；
- 收礼人的地址只存本机，只用于「收下」那一步；导出 JSON 时一并导出（本机数据归用户）；
- 一份礼物只能被领取一次（礼物进入终态后再打开只读）；
- 电子券券码字符集去掉 0 / O / 1 / I（`XXXX-XXXX`）。

## 7. AI 边界

礼遇向 OctoSense 的 AI 暴露三个**只读**工具（`ai.rs`）：

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| `list_gift_catalog` | 可选品类（8 类） | 礼物名、品类、形态、价格 |
| `suggest_gift` | 预算（元）、场合（可选） | 预算内 1–3 件建议 + 一句理由；乔迁 / 结婚 / 宝宝优先家居、母婴等大件品类 |
| `get_gift_box_summary` | 无 | 收到 / 送出 各状态计数、余额、待兑现契约数 |

AI **永远不能**输出：谜题答案、暗号、未揭晓礼物的送礼人、收件地址 / 手机号。
心愿单不暴露给 AI（谁认领了哪件是悬念的一部分）。
没有任何写操作（不能替人送礼、解谜、收下、折现）。测试里对输出做字符串断言。
