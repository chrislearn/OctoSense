# 02 · 流程与状态机

所有流程都在本机模拟：没有服务器、没有真实支付。「对方」的行为由演示模拟器驱动
（见 [05-data-model.md](05-data-model.md#演示模拟器)）。

## 1. 送礼流程（送礼人）

```
[挑礼页] 商品宫格，点一张卡
   │
   ▼
[商品详情] 大图 · 品类 · 名称 · 品牌 · ¥价格 · 卖点标签
   商品介绍（形态 / 规格 / 送达）· 送礼须知 · 同类还有（宫格）
   [送给 TA]  [加到我的心愿单]
   │                      └─▶ 有进行中的心愿单：直接加上，toast「已加到『…』」
   │                          没有：转去发布心愿单，这件已放进去
   ▼
[送礼页] ─────────────────────────────────────────────────────────────
   已选礼物卡（图 · 名称 · 规格 · ¥价格 · 「同类换一件」就地展开同类列表）
   ⓪ 送给谁（仅自己可见的备注，从熟人里点选 / 不指定）
   ① 设置解密游戏  ○猜我是谁  ○专属私密问答  ○专属暗号  ○无条件直接领取
        猜我是谁 → 线索输入框（必填）；答案 = 我的称呼（设置里可改，可写多个别名）
        私密问答   → 问题（必填）+ 答案（必填）
        专属暗号   → 暗号（必填）+ 提示（选填）
   ② 附加契约（可选）开关 → 预设四选一 / 自定义（≤24 字）
   ③ 寄语（选填，≤40 字）
   底栏：合计 ¥109 · 下一步选付款方式   [去结算 ¥109]
   │  校验失败：底栏红字，按钮不跳转
   ▼
[结算页] 确认订单
   订单卡：图 · 名称 · 规格 · ¥价格；送给 / 玩法 / 契约 / 送达 /（心愿）
   付款卡：☑ 优先用余额抵扣（有余额时）· 商品金额 / 余额抵扣 / 还需支付 ·
           付款方式 [微信支付] [支付宝] [银行卡]（全抵扣时隐藏）
   [确认支付 ¥109（微信支付）] / [用余额支付 ¥109]
   │
   ▼
[支付成功]（结算页原地变）这份礼物接下来会怎样 · 订单卡
   [去分享礼卡]  [继续逛逛]
   │
   ▼
[礼卡页] 礼卡预览（玩法 + 线索，不含礼物与价格）
   [复制链接]  [保存礼卡图片]  [以 TA 的视角看看]  [完成]
   │
   ▼
[礼盒 · 送出的] 新的一行：状态「待拆」（约好日子的是「待送达 · 10 月 7 日送到」）
```

要点：

- 顶栏「发起神秘送礼」直接进送礼页（默认第一件），不经过详情；
- 从熟人页某一行点「送礼」进来，⓪ 已选好这位；从回礼提示进来，⓪ 已选好对方，
  且顶部多一行「回礼预算：刚折现的 ¥100」；
- 送礼页只管「送什么、怎么玩」，钱全在结算页算：送礼页校验通过才能去结算，
  结算页只可能因为付款本身出错（`check_send` 与 `send_gift` 的前两步完全一样）；
- 返回键按来路一层层退：结算 → 送礼页 → 商品详情 → 挑礼；付完之后返回栈清空，
  返回直接回到进来的 Tab；
- 离开送礼页（返回到 Tab / 切 Tab）即丢弃草稿，不做草稿箱 —— 这一页一分钟能填完；
- 付款是模拟的：余额抵扣部分从余额扣，其余按所选付款方式记一条流水（「余额抵 ¥20 · 微信支付 ¥89」），
  不影响余额。

## 2. 收礼流程（收礼人）

```
[礼盒 · 收到的] 点一行打开
   │
   ▼
① 解密页（状态 待拆 → 解谜中）
   「你收到一份神秘礼物」+ 玩法徽章
   TA 留下的线索 / 问题 / 暗号提示 卡片
   猜我是谁：6 个候选人芯片（真送礼人 + 熟人 + 通讯录，顺序打乱）或直接输入
   问答 / 暗号：一个输入框
   剩余 N 次机会   [提交答案]
   「猜错了礼物也不会消失哦」
   │  答对 → 揭晓（身份可见）
   │  答错 → 机会 -1，红字「不是 TA，再想想」；
   │  3 次用完 → 揭晓（身份保密：「一位神秘的朋友」）
   │  无条件领取 → 跳过本页，直接揭晓（身份可见）
   ▼
② 揭晓页（状态 已揭晓）
   「恭喜你答对了！这是 [林舟] 送你的礼物」/「礼物拆开了，TA 这次没透露名字」
   礼物卡：名称 · 规格 · 价值 ¥109 · 寄语
   附加契约卡：「收下表示答应：下周找时间回请我喝一杯咖啡」
   [✓ 满意，开心收下]            → ③a
   [↻ 不太喜欢？换购 / 折现余额]  → ③b
   │
   ├─▶ ③a 收下页
   │     有契约：☐ 我同意这个契约（必勾；同意即揭晓 TA 的名字）
   │     实物：收件人 / 手机号 / 地址（必填，演示只校验非空与手机号 11 位）
   │     电子券：无需地址，收下即显示券码
   │     [确认收下] → 状态 已收下；契约进入「契约 · 我答应的」；toast
   │     完成卡：「已收下」+ 券码或「商家将在 48 小时内发货（模拟）」+ [给 TA 回一份礼]
   │
   └─▶ ③b 换购 / 折现页
         分段：[换一份] [折成余额]
         折成余额：价值 ¥109 − 手续费 ¥9（8%）= 退回 ¥100 余额   [确认折现]
         换一份：抵扣额 ¥103（扣 5% 手续费 ¥6），下面是礼物列表，每行显示
                 「退回 ¥x」或「补 ¥y」；点一行 → 确认条 → [确认换购]
         完成卡：「已折现 ¥100」/「已换成 XXX」+ 回礼提示：
                「用刚才变现的余额，给 TA 回送一份『反击礼物』吧！」[去回礼] [以后再说]
```

要点：

- 契约在揭晓页就给看，收礼人在决定前就知道「收下意味着什么」；
- 换购 / 折现后契约**自动作废**，页面上写明；
- 身份保密时依然可以回礼：回礼的收件人是「那位神秘的朋友」，平台代转（演示里直接生成送出记录）。

## 3. 礼物状态机

```
            ┌──────── 撤回（仅送礼人，未打开前）───────▶ 已撤回
            │
  ┌──────┐  打开   ┌───────┐ 答对 / 用完机会 ┌──────┐ 收下 ┌──────┐
  │ 待拆 │───────▶│ 解谜中 │───────────────▶│已揭晓│─────▶│已收下│
  └──────┘        └───────┘                 └──────┘      └──────┘
     │  无条件领取：打开即揭晓 ───────────────▶  │  换购  ┌──────┐
     │                  │                        ├──────▶│已换购│
     └── 7 天未揭晓 ─────┴──▶ 已过期（全额退回送礼人）│  折现  ┌──────┐
                                                 └──────▶│已折现│
                                                          └──────┘
```

| 状态 | 收礼人看到 | 送礼人看到 | 终态 |
| --- | --- | --- | --- |
| 待拆 Sealed | 待拆 · 还剩 N 天 | 待拆 · 对方还没打开 | 否 |
| 解谜中 Opened | 解谜中 · 剩 N 次 | 解谜中 · 猜错 k 次 | 否 |
| 已揭晓 Revealed | 待你决定 | 已揭晓 · 等 TA 决定 | 否 |
| 已收下 Accepted | 已收下 | TA 收下了 | 是 |
| 已换购 Exchanged | 已换成 XXX | TA 换了一份更喜欢的 | 是 |
| 已折现 CashedOut | 已折现 ¥x | TA 折成了余额 | 是 |
| 已过期 Expired | 已过期，已退回给 TA | 已过期 · 已全额退回 | 是 |
| 已撤回 Withdrawn | （收礼人列表里不出现） | 已撤回 · 已全额退回 | 是 |

「已揭晓」不设超时：拆开之后不急着决定，礼物不会跑。

认领心愿时约好日子送到的礼物，到日子之前仍是「待拆」，只是：送礼人看到「待送达 · 10 月 7 日送到」，
可以撤回；收礼人的礼盒里不出现；7 天过期从送到那天算。

## 4. 契约状态机

契约只在**收下**那一刻生成，双方各一份视角：

```
 收下 ──▶ 待兑现 ──(我答应的：标记已兑现 / 答应我的：确认已兑现)──▶ 已兑现
            │
            └──(答应我的：「免了吧」)──▶ 已免除
```

- 期限：收下当天 + 7 天。过了期限显示「已逾期 N 天」，但仍可标记兑现（没有惩罚）；
- 「我答应的」一方不能自己取消 —— 答应了就是答应了；
- 「答应我的」一方可以「免了吧」—— 送礼人大方放过；
- 「提醒 TA」只弹 toast「已发一条温柔提醒（模拟）」，每条契约每天一次。

## 5. 资金流

金额一律以「分」为单位的整数计算，显示时转成 ¥x 或 ¥x.yz。

| 事件 | 余额变化 | 流水标题 |
| --- | --- | --- |
| 新人礼金（演示初始） | +¥20 | 新人礼金 |
| 送礼（余额抵扣部分 a） | −a | 送出 · 礼物名 |
| 送礼（付款方式部分 b） | 0 | 备注「微信支付 ¥b」等（仅记录，`external = b`） |
| 撤回 / 过期退回 | +价格 | 退回 · 礼物名 |
| 折现 | +(价格 − 8% 手续费) | 折现 · 礼物名（手续费 ¥x） |
| 换购，新礼物更便宜 | +(抵扣额 − 新价格) | 换购退差 · 旧 → 新 |
| 换购，新礼物更贵 | −min(余额, 差价)，余下模拟支付 | 换购补差 · 旧 → 新 |
| 演示充值 | +¥50 | 充值（模拟） |

余额只进不出站：不可提现，只能用于送礼、换购补差。

## 6. 通知

三类，设置里各有开关，默认开：

1. **礼物等你拆**：收到的礼物处于待拆 / 解谜中，且离过期 ≤ 2 天：「有一份神秘礼物还没拆，2 天后会退回给 TA」；
2. **契约快到期**：我答应的契约待兑现，且离期限 ≤ 1 天：「你答应的『……』明天到期」；
3. **好友的心愿单**：熟人进行中的心愿单还有没人送的，且离那个日子 ≤ 3 天：
   「林舟的生日还有 3 天，心愿单上还有 3 件没人送」，[去看看] 打开那张心愿单。

每类每次运行最多弹一次；同时只显示一条。不做「TA 刚打开了你的礼卡」这类实时通知 ——
送礼人盯着进度会焦虑，进度去礼盒里看。

## 7. 心愿单流程

### 7.1 发布（主人）

```
[挑礼 · 熟人的心愿单] 顶栏「发布心愿单」/「我的心愿单」行 → [我的心愿单] [发布一张心愿单]
[商品详情]「加到我的心愿单」（还没有进行中的心愿单时）
   │
   ▼
[发布心愿单] ──────────────────────────────────────────────────
   1 · 什么日子  [生日][结婚][乔迁][毕业][宝宝][其他]
                 10 月 9 日 · 周五 · 还有 14 天   [早一天][晚一天][晚一周]
   2 · 标题和想说的话（标题不写就叫「阿岚的生日心愿单」）
   3 · 想要什么（已放的每件一行：图 · 名称 · 预算 / 规格 · [拿掉]）
        [挑一件具体的] → [挑一件放进心愿单] 全目录宫格，点一件就放进来、回到这页
        [说个大概]     → 就地展开：是什么（16 个品类芯片）· 预算（不限 / ¥100 … ¥5000 以内）·
                         要求（≤20 字，如「55 寸以上」）· 实时预览「目录里有 N 件符合」+ 缩略图
                         [放进心愿单] [算了]
   4 · 给谁看  [所有熟人] [林舟] [陈晓] [许宁]（多选，选了具体的人就只给这几位看）
   [发布心愿单]   校验失败：底栏红字
   │
   ▼
[心愿单详情（我的）] toast「心愿单发布了，熟人现在就能看到」
   [编辑] [复制分享链接] [提前结束] [删除]（编辑 / 结束只在进行中时有；删除只在没人认领时有）
   演示卡：[替熟人认领一件] —— 模拟一位熟人认领还没人送的第一件
```

- 编辑走同一个表单（标题「编辑心愿单」，按钮「保存」），已经有人认领的那几件不能拿掉；
- 提前结束：确认条 →「结束后熟人还看得到，但不能再认领」；
- 删除：只有还没人认领时可以（有人认领过就只能结束），确认条 → 删除后回到上一页。

### 7.2 认领（熟人）

```
[挑礼 · 熟人的心愿单] 心愿单卡片：头像字 · 标题 · 日子倒数 · 场合徽章 · 5 张缩略图（有人送的变暗）· 进度
[熟人] 行副标题「生日心愿单 · 还有 3 天 · 3 件没人送」，按钮「看心愿单」
[通知]「好友的心愿单」[去看看]
   │
   ▼
[心愿单详情（好友的）]
   头卡：标题 · 日子 · 想说的话 · 进度条 · 「林舟 发布于 9 月 20 日」
   说明：挑一件还没人送的。送出之后别人会看到「已有人送」，不会撞礼；林舟在拆开礼物之前也不知道是你。
   每件一行：图 · 名称 · 规格 / 预算 · 状态（还没人送 / 已有人送 / 你送的）
     具体的：[送这件] ──────────────────────────────▶ [商品详情]（带心愿上下文）
     说个大概：[帮 TA 挑] ─▶ [帮 TA 挑一件]
                             「陈晓想要一台电视 · ¥3000 以内 · 要求：55 寸以上 · 已按符合程度排好」
                             符合的商品宫格，每张卡一句理由（符合 55寸 · 预算内 / 超出预算）
                             点一张 ─────────────────────────▶ [商品详情]（带心愿上下文）
   │
   ▼
[商品详情] 多一张心愿卡「陈晓的乔迁 · 想要一台电视」「TA 说：55 寸以上 · ¥3000 以内。这件：符合 55寸 · 预算内」
   [就送这件]
   │
   ▼
[送礼页（认领心愿）] 顶部蓝字「认领陈晓的心愿：一台电视」
   送给谁：固定为主人，不能改
   什么时候送到  [10 月 7 日当天送到] [现在就送]（默认当天送到；日子是今天或已过时没有这一段，直接现在送）
   已选礼物：具体的心愿没有「换一件」；说个大概的是「换一件符合的」，只在候选里换
   其余同普通送礼 → 结算（订单多一行「心愿：新家暖房心愿单 · 一台电视」）→ 支付成功
   │
   ▼
支付成功文案：「10 月 7 日那天礼卡才会出现在陈晓的礼盒里，
             在那之前 TA 的心愿单上只显示这件『已被认领』。其他熟人看到『一台电视』已有人送，不会撞礼。」
```

### 7.3 之后

| 事件 | 主人看到 | 其他熟人看到 | 认领人看到 |
| --- | --- | --- | --- |
| 认领（约好日子） | 已被认领 · 10 月 7 日送到 | 已有人送 | 你送的；礼盒·送出的「待送达 · 10 月 7 日送到」 |
| 到了那天 | 礼盒里多一份「一份神秘礼物」；心愿行「已被认领 · 礼物在礼盒里等你拆」 | 已有人送 | 待拆 |
| 主人揭晓 | 「林舟 送的」（身份保密时仍是「已被认领」） | 已有人送 | 已揭晓 |
| 认领人撤回 / 礼物 7 天没拆过期 | 这件变回「还没人认领」 | 还没人送 | 已撤回 / 已过期（全额退回） |
| 过了日子 7 天 / 主人提前结束 | 已结束 | 已结束，没人送的显示「没人送」，不能再认领 | — |

约好日子的礼物：`sent_on` 是约好的那天，`booked_on` 是下单那天；7 天过期从 `sent_on` 算起。
送出详情的时间线先是「下单 · 约好 10 月 7 日送到」，到那天再加「礼卡送到 TA 手里」；
演示模拟器的第一步就是「送到」。
