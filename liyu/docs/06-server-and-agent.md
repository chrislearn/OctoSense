# Server and Octos agent integration

`liyu-server` lives beside this repository. It offers Salvo REST endpoints backed by Diesel/PostgreSQL. `LIYU_API_URL` enables test login as `demo@liyu.test`; `LIYU_IDENTIFIER` selects another test account and `LIYU_AUTH_TOKEN` overrides login. Server-side test users use password `123456`; registration also requires code `123456`. There is no phone/email delivery. The account profile page uses dedicated `/me/profile`, `/me/phone`, `/me/email` and `/me/addresses` endpoints and falls back to a local demo copy on connection failure. Product detail, ordinary shopping cart/test checkout, and role-specific online gift/parcel views now use domain endpoints. `LiyuState::load/save` persists only the separate local demonstration; the server permanently returns 410 for `/api/v1/state` because that whole JSON contains secrets and cannot be the multi-user protocol. Wishlist, wallet, contract and order history pages still need online integration; account identity must be unified across the entire app. See the server README and `_todo.md` for details.

The current OctoSense assistant does **not** operate LiYu by clicking arbitrary UI elements. LiYu advertises a `ServiceManifest` on the AI bus. The host registers that manifest, routes a `ServiceCall` to the matching instance, and returns a `ToolResult`. Both the standalone app's `AiServicePort` and the hosted module's `ServiceExecutor` use the same `ai::answer` implementation. AppCard advertises a separate `ask` tool that submits text to its composer, whose own routing brain and domain agents render cards. A skill is prompt/instruction context; it is not a permission to call an unregistered LiYu action.

LiYu currently offers three read-only tools: `list_gift_catalog`, `suggest_gift`, and `get_gift_box_summary`. The summary deliberately contains counts and balance only. The agent cannot learn a puzzle answer, passphrase, unrevealed sender, delivery address, or phone number through these tools. It also cannot send, accept, exchange, or cash out a gift. To support an AI-assisted action later, add a narrowly scoped tool to the manifest and executor, require the user's explicit confirmation in LiYu's UI, then apply the mutation through the same domain logic used by the UI. Server authorization must enforce the same account and object boundaries. Parallel agents can research catalog and summary in parallel, but must not bypass the tool boundary or race to write the same state revision.
