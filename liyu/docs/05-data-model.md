# 05 · 数据模型

持久化文件：`$MAKEPAD_HOME/liyu/state.json`（micro_serde，宽松反序列化，字段缺失用默认值）。
枚举一律存 `u8`，金额存「分」`i64`，日期存「天序号」`i64`（沿用原 `data.rs` 的日期工具）。

### 礼物 `Gift`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | u64 | 自增 |
| `dir` | u8 | 0 送出 Sent / 1 收到 Received |
| `item` | u16 | 目录下标 |
| `price` | i64 | 下单时价格（分），之后目录改价不影响 |
| `peer` | String | 送出：收礼人备注（可空）；收到：送礼人称呼（别名用 `/` 分隔） |
| `unlock` | u8 | 0 猜我是谁 / 1 私密问答 / 2 专属暗号 / 3 直接领取 |
| `clue` | String | 猜我是谁：线索；私密问答：问题；专属暗号：提示 |
| `answer` | String | 私密问答 / 专属暗号的答案；猜我是谁：送出时存我的称呼，收到时留空（用 `peer`） |
| `contract` | String | 空 = 无契约 |
| `message` | String | 寄语 |
| `sent_on` | i64 | 天序号 |
| `attempts` | u8 | 已用机会 |
| `state` | u8 | 见下 |
| `identity_known` | bool | 揭晓时是否知道送礼人（身份保密后同意契约会变成 true） |
| `solved` | bool | 答对（或直接领取）拆开的，而不是机会用完；时间线据此分两种说法，之后不变 |
| `opened_on` / `revealed_on` / `settled_on` | i64 | 0 = 未发生 |
| `swap_item` | u16 | 换购后的目录下标（`u16::MAX` = 无） |
| `refund` | i64 | 折现 / 换购 / 退回时回到余额的金额（分） |
| `voucher` | String | 电子券券码（收下时生成） |
| `ship_name` / `ship_phone` / `ship_addr` | String | 实物收件信息 |
| `demo_tip` | String | 演示提示（只在演示数据里有） |
| `wish_id` | Option<u64> | 认领的是哪张心愿单（送出的：我认领的；收到的：好友从我的心愿单上认领的） |
| `booked_on` | Option<i64> | 约好日子送到的礼物：下单那天。这时 `sent_on` 是约好送到的那天；`sent_on > today` = 待送达 |

`GiftState`：0 待拆 Sealed · 1 解谜中 Opened · 2 已揭晓 Revealed · 3 已收下 Accepted ·
4 已换购 Exchanged · 5 已折现 CashedOut · 6 已过期 Expired · 7 已撤回 Withdrawn。

送出的礼物中，收礼人的行为由模拟器写回同一条记录（答对与否、收下 / 换购 / 折现）。
待送达的礼物（`is_scheduled`）状态仍是「待拆」，状态文字「待送达 · 9 月 28 日送到」；
收到的列表（`received`）不含待送达的；7 天过期从 `sent_on` 算。

### 心愿 `WishItem`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `item` | Option<u16> | 具体的那件（目录下标）；`None` = 说个大概 |
| `kind` | String | 是什么（`CatalogItem::kind`）；具体的也存一份 |
| `max_price` | i64 | 预算上限（分），0 = 不限；只对说个大概有意义 |
| `wants` | String | 要求，如「55 寸以上」「降噪」 |
| `state` | u8 | 0 还没人送 `WISH_OPEN` / 1 别人认领了 `WISH_BY_OTHERS` / 2 我认领了 `WISH_BY_ME` |
| `gift_id` | u64 | 认领它的礼物 |
| `claimed_on` | i64 | 认领那天 |
| `given_item` | u16 | 实际送的是哪件（`u16::MAX` = 不知道） |

构造：`WishItem::exact(i)` / `WishItem::vague(kind, max_price, wants)`；`title()` 给出「声屿 Air 降噪耳机」或
「一台电视」（量词按类换：一副耳机、一束鲜花……），`sub()` 给出「声屿 · ¥899」或「¥3000 以内 · 55 寸以上」，
`thumb()` 是列表里用的图（说个大概的取同类最便宜的一件；我认领过的换成我送的那件）；`fits(i)`：具体的必须同一件，说个大概的同一类即可。

### 心愿单 `Wishlist`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | u64 | 与礼物共用自增 id |
| `owner` | String | 空 = 我的；否则是好友的称呼 |
| `occasion` | u8 | `OCCASIONS` 下标：生日 / 结婚 / 乔迁 / 毕业 / 宝宝 / 其他 |
| `title` / `note` | String | 标题（≤ 16）/ 想说的话（≤ 40） |
| `event_on` | i64 | 那个日子 |
| `created_on` | i64 | 发布那天 |
| `closed_on` | i64 | 提前结束那天，0 = 没结束 |
| `audience` | Vec<String> | 谁能看见，空 = 所有熟人 |
| `items` | Vec<WishItem> | 1–8 件 |

派生：`is_open(today)`（没结束且 `today ≤ event_on + 7`）、`claimed_count` / `open_count`、
`countdown`（还有 N 天 / 明天 / 就是今天 / 已过 N 天 / 已结束）、`progress_text`、`audience_text`、
`event_name`（「林舟的生日」）。

### 心愿单草稿 `WishDraft`（不持久化）

`id`（`None` = 新发布）、`occasion`、`title`、`note`、`event_on`（新发布默认 today + 14）、`audience`、`items`。
编辑时从 `Wishlist` 拷一份（`WishDraft::from`），离开编辑页就丢。

### 送礼草稿 `SendDraft`（不持久化）

`item`、`peer`、`unlock`、`clue`、`answer`、`contract: Option<String>`、`message`、`use_balance`，以及：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `wish` | Option<(u64, usize)> | 从心愿单来的：（心愿单 id，第几件）；送出即认领 |
| `deliver_on` | Option<i64> | 约好哪天送到（只对心愿单，最晚到那个日子）；`None` = 现在就送 |
| `pay` | Option<u8> | 付款方式（`PAY_METHODS` 下标）；`None` = 流水记「模拟支付」 |

### 契约 `Pact`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | u64 | |
| `gift_id` | u64 | 来源礼物 |
| `text` | String | 契约内容 |
| `peer` | String | 对方 |
| `mine` | bool | true = 我答应的（我是收礼人）；false = 答应我的 |
| `made_on` / `due_on` | i64 | `due_on = made_on + 7` |
| `state` | u8 | 0 待兑现 / 1 已兑现 / 2 已免除 |
| `nudged_on` | i64 | 最近一次「提醒 TA」的日期 |

### 流水 `LedgerEntry`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | u64 | |
| `day` | i64 | |
| `amount` | i64 | 对余额的影响（分，带符号） |
| `external` | i64 | 这笔里模拟支付的部分（分，≥0，不影响余额） |
| `title` | String | 「送出 · 三顿半精品咖啡礼盒」 |
| `note` | String | 「手续费 ¥9」 |

**余额 = Σ amount**，不单独存，避免不一致。

### 熟人 `ContactLocal`

`id`、`label`（只有一个称呼）；统计「送过 / 收到」由礼物按 `peer` 名字匹配算出。
另存一份**通讯录** `directory: Vec<String>`（导入候选 / 猜人候选的名字），
可从 `$MAKEPAD_HOME/liyu/contacts.vcf` 导入 vCard。

### 设置 `Settings`

`nickname`（默认「阿岚」，猜我是谁时对方要猜的名字）、`notify_gift`、`notify_pact`、
`notify_wish`（熟人心愿单提醒，默认开）、
`onboarded`、`theme`（`Option<String>`，存 `ThemeMode::id`；`None` = 没选过，按夜色）、
`ship_name` / `ship_phone` / `ship_addr`（上次填的收件信息，下次收实物时预填，只在本机）。

### 落盘结构 `PersistedState`

`version`、`contacts`、`directory`、`gifts`、`pacts`、`ledger`、`settings`、`next_id`、`wishlists`，
全部是 `Option`：缺字段按默认值补。`version` 必须等于 `STATE_VERSION`（现在是 4），
版本不对的存档不读、不迁移，直接用演示数据。

## 持久化边界

| 存 | 不存 |
| --- | --- |
| 礼物、契约、流水、熟人、通讯录、设置、自增 id、心愿单（我的和好友的） | 目录与商品图（代码常量）、当前页面与返回栈、送礼草稿、心愿单草稿、结算页状态、拆礼阶段、toast、通知已弹标记 |

写盘时机：每次状态变更后立即写（数据量小）；「我 · 导出数据」把同一份写到
`liyu/export-<日期>.json`；读失败（包括版本不对）时用演示数据并 toast 一次「数据读不出来，已用演示数据」。

## 演示模拟器

「送出详情 · 模拟 TA 的下一步」推进一步，结果只由礼物 id 决定（`seed = id * 2654435761`），
便于测试复现。三个判断各取乘积高处的一段（低位只是 id 的余数）：
`g = (seed >> 16) % 4`、`d = (seed >> 20) % 3`、`r = (seed >> 24) % 2`。

| 当前 | 下一步 |
| --- | --- |
| 待拆且待送达 | 送到（`sent_on = today`，出现在 TA 的礼盒里） |
